# 키보드·헤드셋 스테이지 확장 설계

## 목표

완성된 `03.Mouse` 스테이지의 조작, UI, 조명, Desk와 Wall 분위기를 재사용해 `04.Keyboard`와 `05.Headset`을 완성한다. 세 스테이지는 `마우스 → 키보드 → 헤드셋 → 엔딩` 순서로 연결하며, 각 완료 화면에서 다음 단계 또는 메인 메뉴를 선택할 수 있게 한다.

## 범위

- `Assets/ThirdParty/Keyboard.prefab`과 `Assets/ThirdParty/Headset Type1.prefab`을 사용한다.
- 두 스테이지 모두 에어건(먼지 제거)과 헝겊(광택 내기)만 사용한다.
- 좌클릭 청소, 우클릭 회전, Space 오염 확인과 90% 자동 완료 규칙을 유지한다.
- 키보드와 헤드셋의 추억 이미지는 임시 자리표시자로 두고 나중에 사용자 승인 이미지로 교체한다.
- 새로운 청소 도구, 캐릭터 이동과 복잡한 물리는 추가하지 않는다.

## 장비 프리팹 처리

공통 장비 스테이지 빌더가 프리팹의 계층과 Renderer를 실행 전 Editor 단계에서 검사한다. 단일 메시 키보드와 여러 부품으로 나뉜 헤드셋을 같은 규칙으로 처리한다.

1. 활성화된 `MeshRenderer`와 대응하는 `MeshFilter.sharedMesh`를 수집한다.
2. 원본 Renderer와 원본 머티리얼은 그대로 유지한다.
3. 각 유효 메시마다 별도의 먼지 오버레이와 무광 오버레이를 생성한다.
4. 각 메시와 정확히 일치하는 `MeshCollider`를 같은 Transform에 생성한다.
5. 먼지와 광택은 메시별 독립 마스크를 사용해 한 부품을 닦을 때 다른 부품의 같은 UV 위치가 함께 닦이지 않게 한다.
6. 지원 가능한 메시가 하나도 없으면 씬 생성을 중단하고 프리팹 경로가 포함된 명확한 오류를 출력한다.

제작자가 다른 프리팹의 이름이나 자식 순서에는 의존하지 않는다. `mouse_LOD0`처럼 특정 이름을 요구하지 않고 실제 Renderer와 MeshFilter 조합을 기준으로 삼는다.

## 진행도

- 전체 복원도는 모든 활성 먼지·광택 마스크의 평균으로 계산한다.
- 도구 버튼의 개별 진행도는 같은 도구에 속한 모든 메시 마스크의 평균으로 표시한다.
- 작은 헤드셋 부품 하나가 누락되어도 찾을 수 있도록 모든 유효 부품을 포함하되, 전체 진행도가 90%를 넘으면 기존 규칙대로 자동 완료한다.
- 완료 시 모든 남은 마스크를 강제로 완료해 화면을 완전히 깨끗한 상태로 만든다.

## 배치와 카메라

`03.Mouse`의 Desk, Wall, UI 색상과 따뜻한 조명을 `04.Keyboard`, `05.Headset`에 복제한다. 장비마다 원본 스케일과 축이 다르므로 고정 좌표 대신 전체 Renderer Bounds를 사용한다.

- 대상 씬에 `Desk` 또는 `Wall`이 없을 때만 `03.Mouse`의 해당 오브젝트를 복제한다. 이후 사용자가 대상 씬에서 조정한 배치는 빌더가 덮어쓰지 않는다.
- 장비 중심을 회전 피벗에 맞춘다.
- 회전 반경을 계산해 장비가 Desk를 관통하지 않는 높이에 둔다.
- 전체 Bounds가 화면 중앙의 청소 영역에 들어오도록 카메라 거리, near/far clip을 자동 조정한다.
- 원본 프리팹은 씬 최상위의 작성용 오브젝트로 보존하고 비활성화하며, 플레이용 복제본만 빌더 소유 루트 아래에 둔다.

## 추억 완료 화면과 씬 흐름

완료 화면 중앙에는 기존과 같이 이미지 한 장과 추억 대사 한 줄을 표시한다. 그 아래에 같은 너비의 버튼 두 개를 위아래로 배치한다.

```text
[ 다음 단계 진행 ]
[ 메인 메뉴로 돌아가기 ]
```

- `03.Mouse`의 다음 단계: `04.Keyboard`
- `04.Keyboard`의 다음 단계: `05.Headset`
- `05.Headset`의 다음 단계: `06.Ending`
- 모든 메인 메뉴 버튼: `01.MainMenu`

기본 추억 문구는 다음 문장으로 고정한다.

- 마우스: `처음 오락기 앞에 섰던 날, 바라보는 것만으로도 새로운 세계가 열렸다.`
- 키보드: `처음 친구와 나란히 앉아, 같은 게임 속을 함께 달렸다.`
- 헤드셋: `PC방을 가득 채운 우리의 환호가, 아직도 귓가에 선명하다.`

## 코드 구조

- 현재 마우스 전용 씬 조립 코드를 장비 경로, 씬 경로, 장비 이름, 추억 문구와 다음 씬을 받는 공통 조립 함수로 정리한다.
- `MouseStageBootstrap`의 역할은 공통 장비 Bootstrap으로 확장한다. 기존 저장 씬과 프리팹을 다시 생성해 낡은 직렬화 참조를 남기지 않는다.
- `MemoryPanelView`는 다음 단계 버튼과 메인 메뉴 버튼을 각각 연결하고, 전달받은 씬 이름만 로드한다.
- `ToolSelectorView`는 같은 도구의 진행 소스가 여러 개일 때 평균 진행도를 표시한다.
- `01.MainMenu`, `02.Opening`, `06.Ending`의 기존 사용자 소유 오브젝트는 요청 범위 밖이므로 삭제하거나 덮어쓰지 않는다.

## 검증

자동 테스트는 다음 계약을 확인한다.

- `04.Keyboard`, `05.Headset`이 EventSystem과 StageController를 하나씩 포함한다.
- 각 스테이지에 AirGun과 Cloth 진행 소스가 모두 존재하고 CottonSwab은 없다.
- 모든 활성 청소 대상 Renderer에 먼지·광택 오버레이와 대응 MeshCollider가 있다.
- 원본 머티리얼 참조가 플레이용 장비에 보존된다.
- 도구별 진행도가 여러 메시의 평균으로 계산된다.
- 완료 화면의 두 버튼이 위아래 순서로 배치되고 올바른 씬 이름을 사용한다.
- 장비 회전 반경이 Desk 상단보다 높아 모든 각도에서 관통하지 않는다.
- Unity 콘솔 오류가 없고 실제 플레이에서 키보드·헤드셋의 앞뒤와 작은 부품을 청소할 수 있다.

구현은 해커톤 속도 원칙에 따라 공통 흐름을 먼저 구동한 뒤, 실제 플레이에서 카메라 크기·브러시 반경·조명과 오염 가시성을 장비별로 조정한다.
