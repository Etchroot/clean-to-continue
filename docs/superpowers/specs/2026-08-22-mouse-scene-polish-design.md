# 03.Mouse 출품 품질 폴리싱 설계

## 목적

`03.Mouse`를 링크를 처음 연 심사위원이 별도 설명 없이 조작하고, 세 청소 도구의 차이와 깨끗해지는 만족감 및 첫 추억 보상까지 경험할 수 있는 출품 품질의 단일 스테이지로 완성한다. 이 작업에서 만든 구조는 키보드와 헤드셋 스테이지에 재사용할 수 있어야 하며, 사용자 소유 책상과 제3자 원본 에셋을 훼손하지 않아야 한다.

## 범위

이번 작업은 다음 항목을 포함한다.

- 원본 마우스의 색·텍스처·노멀·금속성·광택 정보를 보존하는 청소 재질
- 먼지 제거, 광택 복원과 면봉 틈새 청소의 명확한 시각 피드백
- 따뜻한 추억의 책상 분위기에 맞는 카메라, 조명, 그림자와 배경색
- 오른쪽 진행도 및 세 도구 아이콘 UI의 가독성과 선택 피드백
- 유효한 청소 입력에만 반응하는 입자, 커서 반응과 도구별 사운드
- 90% 자동 완료, 짧은 완료 반짝임과 교체 가능한 추억 이미지 프레임
- 1920×1080 및 1366×768 검수와 첫 Web 빌드 실행

최종 AI 추억 이미지와 외부에서 구매하거나 녹음한 음원은 이번 범위에 포함하지 않는다. 현재 완료 패널은 최종 이미지가 들어갈 비율과 교체 지점을 제공하고, 사운드는 라이선스 의존성이 없는 프로젝트 소유 절차적 효과음을 사용한다.

## 소유권 경계

씬 루트의 `Desk` 프리팹 인스턴스와 사용자가 추가한 장식물은 사용자 소유다. `VerticalSliceSceneBuilder`는 이 오브젝트의 Renderer 경계를 읽어 구도 기준으로 사용할 수 있지만 Transform, Material, 계층, 활성 상태와 프리팹 연결을 변경하지 않는다.

빌더는 `__CleanToContinueVerticalSlice` 표시 아래의 `StageRoot`, 마우스, 카메라, 조명, UI, 입자와 완료 연출만 소유한다. 빌더 재실행 시 이 표시 영역만 교체하고 사용자 소유 루트는 보존한다. `Assets/ThirdParty/Mouse.prefab`이 없거나 유효한 LOD0 메시·Renderer가 없으면 Prototype으로 조용히 대체하지 않고, 원인과 필요한 에셋 경로를 포함한 명확한 빌드 오류를 낸다.

## 선택한 구현 방식

재실행 가능한 빌더 기반 선택적 폴리싱을 사용한다. 씬을 손으로만 조정하는 방식은 빠르지만 재생성 시 손실되고 다른 장비로 복사하기 어렵다. 범용 ScriptableObject 스테이지 프레임워크를 먼저 만드는 방식은 확장성은 높지만 현재 해커톤 범위에 비해 과하다.

`VerticalSliceSceneBuilder`는 최상위 조립 순서만 담당한다. 재질 복사, 따뜻한 조명, UI 아이콘과 청소 피드백 조립은 작은 Editor 헬퍼로 분리한다. 런타임 입력·진행도·완료 규칙은 이미 검증된 기존 컴포넌트를 유지하고, 시각·청각 피드백을 전달하는 좁은 컴포넌트만 추가한다.

## 원본 마우스 재질 보존

원본 마우스 Material은 읽기 전용 기준이다. 빌더는 원본 Renderer의 Material에서 다음 의미의 값을 찾아 프로젝트 소유 `MouseCleanable` Material에 복사한다.

- Base Map: `_BaseMap` 또는 `_MainTex`
- Base Color: `_BaseColor` 또는 `_Color`
- Normal Map: `_BumpMap` 또는 URP의 호환 노멀 속성
- Metallic Map 및 metallic 값
- Smoothness 또는 glossiness 값
- Base Map의 tiling과 offset

속성이 없으면 흰 텍스처, 흰 Base Color, 비금속과 중간 광택을 사용한다. 원본 Material과 FBX 내장 Material은 수정하지 않는다. 청소 셰이더는 복사된 원본 표면을 먼저 계산한 뒤 먼지 마스크로 색과 광택을 낮추고, 헝겊 마스크가 지워진 위치에서 원래 광택 상한을 복원한다.

## 따뜻한 추억의 책상 연출

마우스는 사용자가 배치한 `Desk` 상판 위의 시각 중심에 놓는다. 빌더는 Desk Renderer들의 합산 Bounds로 상판의 중심과 높이를 계산하되 Desk를 이동하지 않는다. 계산할 수 없으면 현재 마우스 위치와 고정 구도를 유지하고 경고를 남긴다.

조명은 세 역할로 제한한다.

- 따뜻한 주광: 스탠드 조명처럼 위·측면에서 들어오는 호박색 빛
- 중립 보조광: 반대편 형태가 검게 뭉개지지 않게 하는 약한 빛
- 얇은 림 또는 반사 강조: 헝겊으로 복원된 광택을 읽게 하는 제한된 밝은 선

카메라는 마우스가 UI를 제외한 플레이 영역의 중앙에 충분히 크게 보이도록 하고, 책상 가장자리는 공간을 설명할 정도만 포함한다. 고정 카메라를 유지하며 캐릭터 이동이나 자유 줌은 추가하지 않는다.

## 도구별 청소 피드백

### 에어건

먼지는 따뜻한 회갈색의 반투명 막으로 원본 표면 위에 나타난다. 유효한 표면 적중 동안 브러시 중심에서 짧은 먼지 입자가 바깥으로 흩어지고, 원본 색과 표면 세부가 즉시 드러난다. 입자 수는 프레임마다 무제한 생성하지 않고 하나의 재사용 ParticleSystem 방출량으로 제어한다.

### 면봉

기존 큰 구체 대신 휠·버튼 틈을 따라 붙은 작고 불규칙한 먼지 덩어리 네 개를 사용한다. 각 지점은 클릭 판정을 위한 Collider와 표시용 자식을 분리한다. 청소될수록 표시가 줄고 살짝 흔들리며, 완료 시 짧은 튀김 입자 후 사라진다. 면봉 입력은 표면 Collider 뒤에 있어도 현재 도구 대상 탐색으로 선택된다.

### 헝겊

별도 얼룩 무늬를 추가하지 않는다. 닦기 전에는 원본 색을 유지하되 반사가 흐리고, 닦은 위치에서 Smoothness와 조명 하이라이트가 복원된다. 따뜻한 주광과 림 조명은 이 변화가 카메라 각도에서 보이도록 배치한다.

잘못된 도구나 UI 위 클릭은 진행도, 입자와 적중 피드백을 발생시키지 않는다. 도구 루프 사운드는 기존 입력 시작·UI 진입·포커스 상실·완료 잠금 규칙을 유지한다.

## UI와 안내

오른쪽 상단 진행 휠과 오른쪽 세로 도구 패널을 유지한다. 패널은 따뜻한 검정에 가까운 반투명 배경, 아이보리 글자와 호박색 선택 테두리를 사용한다. 도구 버튼은 에어건, 면봉과 접힌 헝겊을 읽을 수 있는 프로젝트 소유 단색 아이콘 Sprite를 사용하며 `1`, `2`, `3` 단축키를 함께 표시한다.

선택 도구는 1.08배 확대, 4픽셀 테두리와 접근 가능한 텍스트 상태로 구분한다. 각 도구의 개별 진행도와 완료 체크를 유지한다. 최초 진입 안내는 좌클릭 청소, 우클릭 회전, `Space` 강조를 간단히 보여 주고 첫 유효 입력 후 시야를 가리지 않게 약해진다.

## 완료 연출

세 진행도의 평균이 90%에 도달하면 기존 규칙대로 입력을 잠그고 남은 오염을 정리한다. 진행 휠은 0.35초 동안 100%로 채워지고, 마우스 표면을 따라 짧은 따뜻한 반짝임과 완료 차임을 재생한다. 그 뒤 배경이 어두워지고 중앙에 16:9 추억 이미지 프레임, 아래에 한 줄 대사와 계속 버튼이 나타난다.

이번 범위의 이미지 프레임은 최종 AI 이미지가 없어도 의도한 크기·여백·대비를 검수할 수 있는 프로젝트 소유 자리표시자다. 최종 이미지 교체는 `MemoryPanelView` 참조 한 곳에서 가능해야 한다.

## 데이터 흐름

1. `StageInputController`가 포인터, 클릭, 회전, 도구 단축키와 `Space`를 읽는다.
2. `StageInteractionController`가 현재 도구가 처리할 수 있는 Raycast 적중을 거리순으로 찾는다.
3. 표면 도구는 `SurfaceMaskLayer`에 UV와 브러시 반경을 전달하고, 면봉은 `GapDirtGroup`에 Collider와 제거량을 전달한다.
4. 청소 대상은 진행도 변경과 유효 적중 피드백을 분리해 알린다. 이미 집계된 진행도 셀에서도 시각 마스크는 계속 갱신할 수 있다.
5. 피드백 컴포넌트가 현재 도구, 적중 위치와 실제 제거 여부에 맞춰 입자·커서·짧은 적중음을 갱신한다.
6. `StageController`가 세 진행도를 합산하고 90%에서 입력 잠금, 강제 정리와 완료 패널을 한 번만 실행한다.

## 오류와 복구

- Mouse 프리팹 또는 LOD0가 없으면 빌더는 경로를 포함한 오류로 중단하고 기존 저장 씬을 덮어쓰지 않는다.
- Desk가 없거나 Renderer Bounds를 계산할 수 없으면 사용자 작업을 막지 않고 현재 고정 카메라·마우스 위치로 조립하며 경고를 남긴다.
- 원본 Material 속성이 없으면 안전한 기본값을 쓰고 청소 마스크 기능은 유지한다.
- Web 플랫폼에서 지원되지 않는 셰이더 기능은 사용하지 않는다. Compute Shader, 실시간 유체와 화면 전체 후처리는 제외한다.
- 빌더 재실행 중 생성 실패가 발생하면 기존 사용자 소유 Desk와 장식물은 그대로 남아야 한다.

## 성능과 Web 기준

기존 32×32 진행도 격자와 256×256 시각 마스크를 마우스 스테이지 기본값으로 유지하고 실제 화면에서 부족할 때만 512×512로 올린다. 입자는 하나의 시스템을 재사용하고 동시 입자 수를 제한한다. 새 외부 런타임 패키지를 추가하지 않으며 브라우저 자동 재생 정책에 따라 첫 사용자 입력 이후에만 오디오를 시작한다.

첫 Web 빌드는 Chrome과 Edge에서 설치·로그인 없이 실행해야 한다. 좌클릭 청소, 우클릭 회전, 숫자키, `Space`, 오디오 시작, 탭 포커스 상실, 새로고침과 완료 패널을 확인한다.

## 테스트와 완료 기준

자동 테스트는 다음 회귀를 보호한다.

- 원본 Material의 호환 속성이 프로젝트 소유 청소 Material로 복사됨
- 원본 Material과 ThirdParty 프리팹이 변경되지 않음
- 빌더 재실행 후 사용자 소유 `Desk` Transform과 프리팹 연결이 동일함
- 저장된 마우스의 표시 메시와 MeshCollider가 모두 LOD0를 사용함
- 유효한 도구 적중만 진행도와 피드백을 발생시킴
- 면봉 대상이 표면 뒤에 있어도 선택되고 표면 도구는 틈새 Collider에 막히지 않음
- 89.9%에서는 진행 중이며 90%에서 완료가 한 번만 실행됨
- 항상 포함할 셰이더와 Web 빌드 설정이 유지됨

완료 판정에는 다음 증거가 모두 필요하다.

- Game View 포커스 상태의 PlayMode 전체 통과
- EditMode 전체 통과
- Unity 콘솔의 게임 코드 오류 0건
- 1920×1080과 1366×768에서 마우스·Desk·UI 겹침 없음
- 사용자가 `03.Mouse`를 처음부터 90% 완료 보상까지 직접 플레이
- Chrome과 Edge에서 첫 Web 빌드의 입력·오디오·완료 흐름 통과

## 범위에서 제외하는 항목

- Desk Transform과 Material의 자동 수정
- 최종 AI 추억 이미지 생성·선정
- 외부 유료 또는 구매 음원의 최종 적용
- 키보드·헤드셋 씬 구현
- 자유 카메라, 캐릭터 이동, 복잡한 액체 물리
- 범용 장비 데이터 프레임워크의 전면 리팩터링
