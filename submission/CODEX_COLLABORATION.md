# Codex와 함께 게임을 만든 과정

이 문서는 공식 신청서의 선택 가산점 항목에 맞춰 지속적으로 갱신한다.

## 제출용 요약

### 제작 방식과 규모

- 이번 프로젝트는 **제작자가 C# 코드를 한 줄도 직접 입력하지 않고 게임을 완성하는 것**에 초점을 맞췄다.
- 제작자는 자연어로 기능, 수정 사항과 플레이 피드백을 전달하고, Codex가 Unity C# 코드·셰이더·Editor 도구·테스트·WebGL 빌드를 작성했다.
- 개발 기간은 기록상 **2026년 8월 15일~23일**, 달력 기준 9일(실제 경과 약 8일)의 집중 개발이었다.
- Codex 사용량은 정확한 API 계측값이 아닌 사용자 체감 추정치로, **ChatGPT Plus 주간 사용 한도의 약 250%**, 즉 약 2.5주 분량을 한 주 안팎에 사용한 수준이다.
- Unity 공식 MCP Server와 Codex를 연결해 파일만 수정한 것이 아니라 열린 씬, GameObject, 컴포넌트와 콘솔을 확인하고 Editor 명령·테스트·WebGL 빌드까지 실행했다.

### Codex를 어디에 사용했나요?

- 해커톤 요구사항을 분석하고 하루 제작 취지에 맞는 제한형 3D 청소 게임으로 범위를 정하는 데 사용했다.
- 게임 구조, Unity 프로젝트, C# 런타임 코드, URP 셰이더, UI, 오디오, 씬 전환과 자동 테스트를 구현하는 데 사용했다.
- Unity MCP 연동으로 씬과 오브젝트 구조를 읽고, Editor 빌더를 실행해 여섯 씬을 생성·수정하며 콘솔 오류를 확인했다.
- Asset Store 프리팹의 메시·UV·재질·Collider 차이를 분석하고 마우스·키보드·헤드셋에 공통 청소 시스템을 적용했다.
- WebGL 빌드, 브라우저 재생 문제, 제출용 ZIP 구조와 개발·Human-in-the-loop 문서를 관리했다.
- 비전공자 제작자가 나중에 이해할 수 있도록 코드 구조와 문제 원인을 쉬운 한국어 문서로 기록했다.

### 어떤 기능을 구현했나요?

- 마우스, 키보드, 헤드셋을 순서대로 청소하는 3개의 3D 스테이지를 구현했다.
- 에어건으로 먼지를 제거하고 헝겊으로 광택을 복원하며, 오른쪽 UI에서 두 도구를 자유롭게 바꿀 수 있게 했다.
- 좌클릭 청소, 우클릭 회전, `Space` 잔여 오염 강조와 90% 자동 완료 규칙을 구현했다.
- UV 마스크와 폴리곤 기반 방식을 함께 사용해 서로 구조가 다른 세 프리팹에서 클릭한 부분만 청소되게 했다.
- 원형 복원도·퍼센트, 도구 아이콘, 조작 안내, 완료 차임과 추억 이미지·문구 보상을 구현했다.
- 인트로 영상, 메인 메뉴, 설정, 크레딧, 텍스트 오프닝, 세 장비 씬과 엔딩을 연결했다.
- 반복 BGM, 도구별 효과음, 버튼 클릭음, 버튼 호버, 씬 전환 페이드와 음량 설정을 구현했다.
- 설치 없이 실행되는 Unity WebGL 빌드와 itch.io 업로드용 ZIP을 제작했다.
- 마지막 검증 기준으로 EditMode 26개와 PlayMode 63개의 자동 테스트를 구성했다.

### 어떤 문제를 해결했나요?

- 보이는 마우스 메시와 청소용 Collider의 LOD가 달라 일부 폴리곤이 청소되지 않던 문제를 같은 메시로 맞춰 해결했다.
- 키보드가 깨끗해 보여도 87%에서 멈추던 문제를 실제 UV 삼각형이 사용하는 영역만 진행도로 계산하도록 수정했다.
- UV가 없는 헤드셋에서 파츠 전체가 한 번에 변하던 문제를 클릭 주변 폴리곤만 제거하는 방식으로 해결했다.
- 헤드셋 `Muffs` 클릭을 부모 파츠가 먼저 가져가 청소되지 않던 문제를 실제 클릭된 자식 Collider 우선 처리로 해결했다.
- WebGL에서 한글 UI가 사라지거나 잘리던 문제를 한글 폰트 포함과 텍스트 영역 조정으로 해결했다.
- 씬 전환 후 BGM이 끊기거나 MainMenu·Opening·Ending이 무음이던 문제를 영속 음악 재생기, 브라우저 사용자 입력 재시도와 씬별 AudioListener 보장으로 해결했다.
- 엔딩 버튼이 동작하지 않던 문제, 도구 이미지 비율 왜곡, UI 배치와 밝은 배경 위 텍스트 가독성 문제를 실제 Web 빌드 피드백에 따라 수정했다.
- 씬 빌더가 사용자가 배치한 Desk·Wall·장비 Transform을 덮어쓰지 않도록 프로젝트 소유 영역과 사용자 소유 영역을 분리했다.
- 기능마다 실패 테스트로 문제를 재현한 뒤 수정하고, Unity 콘솔과 실제 Web 빌드로 다시 확인했다.

### 사람이 직접 결정한 부분은 무엇인가요?

- 제작자가 게임의 핵심 소재를 ‘게이밍 장비를 청소하며 추억을 복원하는 게임’으로 정하고 제목 `Clean to Continue`를 선택했다.
- 마우스 → 키보드 → 헤드셋 순서, 에어건·헝겊 두 도구, 90% 완료, `Space` 강조와 추억 사진 보상 구조를 직접 결정했다.
- 따뜻한 추억의 책상 분위기, 메인 메뉴·오프닝·엔딩 구성, 회상 문구와 각 장면의 감정 흐름을 결정했다.
- 사용할 3D 모델, 책상, 이미지, 영상과 음원을 직접 선택했으며 Desk·Wall·장비의 크기와 위치도 Unity에서 직접 조정했다.
- 처음부터 완벽하게 다듬기보다 전체 흐름을 빠르게 완성한 뒤 실제 플레이로 문제를 찾는 개발 원칙을 정했다.
- 매 단계 Unity와 Web 빌드를 직접 플레이하고 청소 누락, 진행도 정체, 오디오, UI와 가독성 문제를 찾아 수정 방향을 지시했다.
- Codex는 구현 방법과 대안을 제안했지만 게임의 범위, 미감, 조작, 에셋과 최종 채택 여부는 제작자가 승인했다.

## Codex를 어디에 사용했나요?

- 해커톤 조건 조사와 게임 범위 결정
- Unity 프로젝트 구조, C# 코드, 셰이더, UI와 테스트 구현
- Unity 공식 MCP를 통한 Scene·GameObject·콘솔 확인
- Web 빌드 오류 분석과 브라우저 검증
- 비전공자용 설명, 개발 로그와 제출 자료 작성
- Git 변경 관리와 코드 리뷰

## 어떤 기능을 구현했나요?

기획부터 세 장비의 전체 플레이 흐름과 최종 미디어 연결까지 Codex와 함께 구현했다. 구현이 완료될 때마다 기능, 파일, 테스트와 관련 HIL ID를 추가한다.

구현 완료 기능:

- 에어건·헝겊 두 청소 도구의 선택과 중복 변경 방지 규칙
- Codex가 열려 있는 Unity에서 실제 EditMode 테스트를 비동기로 실행하고 결과를 읽는 검증 명령
- 같은 위치의 반복 청소를 중복 계산하지 않는 표면 범위 규칙과 세 오염의 동일 가중 90% 자동 완료 규칙
- Web 호환 더블 버퍼 GPU 마스크, 도구별 표면 라우팅과 URP 조명 기반 광택 복원
- 진행도를 바꾸지 않는 1.2초 잔여 오염 강조
- 코드 생성 Input System 액션, `Cleanable` 전용 Raycast, UI 시작 클릭 차단과 제한된 우클릭 장비 회전
- 사용자가 제안한 번호 체계로 여섯 씬을 선행 생성하고, 열린 씬과 사용자 오브젝트를 보존하는 재실행 가능한 Editor 빌더
- 90% 완료 1회·입력 잠금·강제 정리를 연결하는 스테이지 컨트롤러와 진행 휠·도구 선택·마우스 추억 보상 View
- 고정 난수 씨앗으로 재현 가능한 44.1kHz 도구별 임시 루프음과 세 음 완료 차임
- `01.MainMenu` 시작·설정·크레딧, 10초/건너뛰기 `02.Opening`, 실제 Asset Store Mouse 프리팹을 청소 대상으로 연결한 `03.Mouse`와 재사용 `StageRoot`
- 생성 표시가 있는 프로젝트 소유 루트만 갱신하고 사용자 씬 오브젝트를 보존하는 세로 슬라이스 빌더, HIL-020에 따른 Desk 수동 배치 경계
- 키보드 UV 빈 공간을 제외하는 진행도 계산과 UV가 없는 헤드셋을 위한 클릭 주변 폴리곤 청소, 사용자 배치를 보존하는 선택 보정 메뉴
- 사용자 제공 인트로 영상·타이틀/엔딩·도구/앨범 이미지·BGM을 여섯 씬에 연결하고 Web 영상 경로, 영속 BGM, 라운드 UI와 세 음 완료 차임을 자동 검증하는 최종 미디어 빌더
- 실제 Web 빌드에서 발견된 BGM 수명주기·영상 종료 이벤트·한글 폰트·브라우저 오디오 정책 문제를 수정하고 인트로→메뉴→오프닝을 오류 없이 검증한 브라우저 회귀 과정
- 사용자가 업로드본에서 발견한 UI·BGM·엔딩 클릭 문제를 저장 씬과 브라우저 화면으로 재현하고, 큰 텍스트 잘림·음악 중복·입력 모듈 누락 원인까지 테스트로 고정한 배포 회귀 수정
- 일반 0.35초, 엔딩 전환 0.7초의 공통 검정 페이드와 전환 중 중복 입력 차단

최종 상태:

- WebGL 빌드와 itch.io 업로드본 플레이 검증을 완료했다.
- EditMode 26개와 PlayMode 63개의 자동 테스트를 구성했다.
- 공개 URL·썸네일·데모 영상은 제출 폼에서 사용자가 최종 입력한다.

## 어떤 문제를 해결했나요?

- 하루 제작 취지와 3D 품질 사이의 범위를 제한형 3D로 조정했다.
- 세 장비를 별도 게임으로 만들지 않고 공통 시스템으로 재사용하도록 설계했다.
- 공개 저장소에서 Asset Store 원본이 재배포되지 않도록 분리 정책을 만들었다.
- Codex가 Unity 파일뿐 아니라 실행 상태를 확인할 수 있도록 공식 MCP 경로를 선택했다.
- Unity Hub 구버전 제거 충돌을 사용자와 함께 해결하고 Unity 6000.3.22f1, WebGL 모듈과 Visual Studio 설치를 검증했다.
- Universal 3D 템플릿의 Input System 1.12.0 컴파일 문제를 공식 지원 버전 1.17.0으로 수정했다.
- 공식 MCP를 연결해 Unity 콘솔의 오류·경고와 열린 씬의 `Main Camera`, `Directional Light` 및 컴포넌트를 직접 읽어 검증했다.
- 사용자와 청소 표현 방식을 비교해 표면 마스크, 틈새 오브젝트와 Unity 조명 기반 광택 복원을 결합한 Web 친화적 구조로 구체화했다.
- 마우스 세로 슬라이스를 규칙 테스트, Unity MCP 장면 검증과 실제 Chrome·Edge Web 빌드 검수까지 추적 가능한 8개 구현 작업으로 나눴다.
- 사용자가 고른 네 프리팹의 메시·UV·재질·콜라이더·누락 스크립트와 파일 의존성을 검사해 마우스가 실시간 청소 마스크에 적합함을 확인했다.
- Asset Store 원본을 `ThirdParty/Source` 아래로 정리하고 Git 제외 상태를 유지했으며, 사용하지 않는 데모 코드의 컴파일 오류는 원본 삭제 없이 해당 로컬 어셈블리만 비활성화해 해결했다.
- MCP 명령 안의 동기 Test Runner가 Unity 업데이트 루프를 막는 문제를 재현한 뒤, 비동기 Editor 메뉴 명령과 결과 JSON 방식으로 바꿔 테스트 2개 통과와 콘솔 오류 0건을 검증했다.
- 정확히 90%인 값이 부동소수점 누적 오차로 미완료되는 실패 테스트를 근거로 합산 정밀도를 수정하고, 경계·중복 조건을 포함한 EditMode 테스트 8개 통과를 확인했다.
- 실제 PlayMode 테스트가 발견한 MonoBehaviour 네이티브 객체 생성 시점 오류를 지연 초기화로 수정했다. 별도 코드 리뷰에서 Web 빌드의 숨김 셰이더 제거 위험을 찾아 Player 빌드 포함 설정과 회귀 테스트를 추가했으며, GPU 수명주기·스탬프·도구 라우팅·두 마스크 공존을 EditMode 11개와 PlayMode 4개 테스트로 검증했다.
- 새 테스트가 발견되지 않은 것처럼 보인 현상을 Unity Editor 로그로 추적해, 실제 원인은 공통 진행도 인터페이스 구현 누락으로 인한 컴파일 중단이고 표시된 JSON은 이전 실행 결과였음을 구분했다. 결과 갱신 시각과 개수를 함께 확인하는 방식으로 바꾸고, 코드 리뷰가 찾은 누락 틈새 참조의 진행도 오류까지 회귀 테스트로 수정해 EditMode 15개와 PlayMode 5개를 검증했다.
- 입력 작업에서는 실제 Camera·Collider·오염 컴포넌트로 다섯 PlayMode 회귀 테스트를 만들었다. 첫 실패를 콘솔로 분석해 빈 틈새 그룹이 완료 상태를 반환하는 기존 계약과 면봉 픽스처의 누락 표면이라는 테스트 준비 문제를 분리했고, 세 오염을 모두 가진 픽스처로 고쳐 EditMode 21개와 PlayMode 10개를 Unity Editor에서 검증했다. 이 과정으로 잘못된 도구 차단, 우클릭 회전 우선, UI 위에서 시작한 누름의 해제 전 차단을 근거화했다.
- 코드 검토로 발견한 `Space` 하이라이트 의존성 누락은 실제 가상 Keyboard 입력을 이용한 회귀 테스트로 재현했다. Input System 액션이 활성 상태인 채 `Space`, `1`, `2`, `3` 장치 이벤트를 처리하는지 검증하고, 직접 하이라이트 참조를 우선 사용하며 상호작용 컨트롤러에도 동기화하도록 수정해 PlayMode 12개 통과를 확인했다.
- 후속 검토에서는 직접 참조가 없을 때의 동기화가 상호작용 컨트롤러의 기존 하이라이트를 지우는 반대 경로를 찾아냈다. 실제 `Space` 장치 이벤트 회귀 테스트로 재현한 뒤, 비어 있지 않은 직접 참조만 동기화하도록 수정해 두 연결 방식을 모두 보호하고 PlayMode 13개 통과를 확인했다.
- 사용자가 확인 가능한 씬을 먼저 만들자는 방향 변경을 반영해 여섯 번호형 씬을 생성했다. 테스트가 발견한 “열어 둔 씬을 빌더가 닫는 문제”와 코드 리뷰가 발견한 “동일 이름의 사용자 카메라·UI 설정을 덮어쓰는 문제”를 수정했다. 실제 게임 씬을 건드리지 않는 Preview Scene·임시 복사 씬 회귀 테스트를 포함해 씬 존재·정확한 공통 구조·빌드 순서·재실행 안전성을 EditMode 20개와 PlayMode 5개로 검증했다.
- 스테이지 완료 연결에서는 테스트를 먼저 작성해 UI·스테이지 형식이 없는 컴파일 실패를 확인한 뒤, 실제 진행 모델의 90% 완료 이벤트가 입력을 잠그고 추억 패널의 실제 열림 이벤트를 한 번만 발생시키도록 구현했다. 기존 씬과 입력 코드를 건드리지 않은 상태에서 EditMode 21개와 PlayMode 14개 통과를 확인했다.
- 후속 코드 리뷰에서 UI 누름이 원시 좌클릭 오디오를 시작하는 문제, 완료 후 도구 버튼 콜백이 남는 문제와 89.9%가 90%로 보이는 문제를 찾았다. 실제 임시 AudioSource·Button·Text를 사용하는 RED→GREEN 회귀 테스트 3개로 UI 오디오 차단, 완료 버튼 잠금과 교차 진행도 스냅샷을 보호했고 PlayMode 17개 통과를 확인했다.
- 추가 리뷰에서는 게임 영역에서 누른 채 UI로 이동하면 held 상태가 바뀌지 않아 소리가 계속되는 경로를 발견했다. 실제 가상 Mouse와 Input System UI 모듈로 실패를 재현하고 held/UI 컨텍스트 변화와 누름 시작점을 기억하도록 최소 수정해, 유효 누름의 UI 진입 정지·이탈 재개와 UI 시작 누름의 계속 무음을 PlayMode 18개로 검증했다.
- 세로 슬라이스 조립에서는 먼저 씬 스모크 테스트를 작성해 시작 버튼·오프닝 전환·세 도구·완료 UI가 없는 RED를 확인한 뒤, 번호형 씬의 프로젝트 소유 영역만 채우는 빌더와 런타임 흐름을 구현했다. 빌더 재실행 테스트 과정에서 이전 `MainMenuView`와 `OpeningSequence`가 남아 참조가 끊기고 중복되는 문제를 발견해, 표시된 소유 루트의 알려진 생성 컴포넌트만 제거하도록 수정했다.
- Unity MCP로 `03.Mouse` Hierarchy와 프리팹 원본 경로를 직접 읽어 플레이 대상이 `Assets/ThirdParty/Mouse.prefab`임을 확인하고, 원본 수정이나 PrototypeMouse 생성 없이 세 진행도 소스·회전·완료 패널이 연결된 것을 검증했다. 사용자가 책상 배치를 직접 맡기로 한 HIL-020 변경은 빌더의 모든 Desk 생성 경로를 제거하고 에셋 크레딧을 `도입·미통합`으로 정정해 반영했다.
- 사용자의 실제 플레이 보고를 출발점으로 청소 입력을 `Raycast → Collider 메시 → UV → CPU 진행도 격자 → GPU 시각 마스크` 순서로 추적했다. 진행도 격자와 시각 마스크의 해상도 차이, 표시용 LOD0와 충돌용 LOD3 불일치, 첫 Collider만 선택하는 면봉 라우팅을 각각 독립 RED 테스트로 재현한 뒤 최소 수정했으며, 최종 PlayMode 27개와 EditMode 21개 통과 및 사용자 에어건 재확인까지 기록했다.
- 키보드가 화면상 모두 깨끗해도 87%에 머무는 현상은 UV 사각형의 빈 공간까지 진행도로 세던 것이 원인이었다. 헤드셋은 여섯 파츠의 UV가 모두 `(0,0)` 한 점이라 마스크가 파츠 전체에 적용됐다. 실제 UV 삼각형 점유 격자와 UV 없는 메시용 삼각형 제거 모드를 각각 RED→GREEN으로 구현하고, 읽기 가능한 헤드셋 오버레이 메시·상단 조명·80% 브러시 반경을 사용자 Transform 보존 보정으로 적용했다. 최종 EditMode 23개와 PlayMode 40개가 모두 통과했다.
- 사용자가 실제 플레이에서 발견한 헤드셋 `Muffs` 청소 불가 문제를 Codex가 Collider·오버레이·Raycast·입력 우선순위로 나눠 진단했다. 360개 표면 지점 모두 Collider에 명중해 가려짐 가설을 배제하고, 자식 클릭을 부모 `EarSide`가 먼저 소비하는 경로를 회귀 테스트로 재현했다. 정확한 Collider 파트를 우선하도록 최소 수정해 EditMode 23개와 PlayMode 41개 통과를 확인했다.
- 사용자의 업로드 플레이 피드백을 바탕으로 Codex가 원본 이미지 크기와 저장 씬의 `Image.Type`을 비교해 1:1 에셋이 `Sliced`로 남아 늘어나는 원인을 확인했다. RED 테스트에서 BGM 시작·이미지 유형·패널 폭·버튼 클릭음 실패를 재현한 뒤 수정했다.
- 인트로 영상은 무음으로 유지하면서 BGM을 즉시 요청하고 첫 입력을 Web 자동 재생 제한의 재시도 지점으로 사용한다. 모든 표시 버튼에는 효과음 음량을 따르는 코드 생성 `딸깍` 소리를 연결했다.
- 최종 검증은 EditMode 26개, PlayMode 57개 통과와 로컬 WebGL의 인트로 → 메뉴 → 오프닝 → 마우스 화면 확인으로 수행했다. 브라우저 경고·오류는 0개였고 정사각형 도구 이미지와 축소된 조작 패널을 실제 렌더링에서 확인했다.
- 사용자가 업로드본에서 MainMenu·Opening·Ending의 무음을 발견하자 Codex는 씬별 `AudioListener` 개수를 비교해 장비 씬 1개, 문제 씬 0개라는 차이를 특정했다. 수정 전 실패 테스트로 리스너·Web 클릭 재개·호버 동작을 재현한 뒤 공통 빌더와 두 UI 컴포넌트를 수정했다.
- 최종 회귀 테스트는 `MainMenu → Opening → Ending`에서 동일한 지속 음악 재생기와 각 씬의 활성 리스너 1개를 검증한다. EditMode 26개와 PlayMode 61개가 통과했고 갱신된 WebGL 빌드를 생성했다.
- 사용자가 완료 화면의 실제 가독성 문제를 지적한 뒤, Codex는 사진·문구·첫 버튼의 기존 좌표를 비교해 문구가 버튼과 약 8px밖에 떨어지지 않은 배치를 확인했다. 새 위치·글자 크기와 엔딩 외곽선·그림자를 실패 테스트로 고정하고 세 장비 씬에 동일하게 적용해 PlayMode 63개 통과를 확인했다.

## 사람이 직접 결정한 부분은 무엇인가요?

핵심 결정은 `docs/HUMAN_IN_THE_LOOP.md`의 HIL 항목에 순서대로 기록되어 있다. 특히 게임 소재, 장비 순서, 청소 단계, 진행 UI, 추억 장면, Unity 선택, 제목, 전체 Codex 개발, GitHub 공개 범위, 설치·연결 확인과 최종 에셋 선택은 사용자가 직접 제안하거나 최종 선택했다.

HIL-019부터는 해커톤 개발 속도를 높이기 위해 사용자가 직접 정한 “최소 동작 구현 → 전체 흐름 완성 → 통합 테스트와 순차 안정화” 원칙도 Codex 작업 지침으로 적용한다.

HIL-020에서는 Desk Table White의 배치와 위치 결정을 사용자가 Unity에서 직접 맡고, Codex 빌더는 실제 Mouse 중심의 카메라·조명·청소 흐름만 관리하도록 경계를 다시 정했다.
